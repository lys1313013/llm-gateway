# 日志与模型测试授权

`/api/test/chat`、`/api/test/messages` 与日志、会话接口使用登录身份，客户端的 `team_id` 不能作为授权依据。

| 调用者 | 模型测试 | 日志、会话与统计 |
|---|---|---|
| root | 可以显式选择其他团队测试其路由 | 全部记录，含历史无所有者记录 |
| 团队管理员 | 仅本团队，可测试尚未暴露的路由 | 仅当前属于本团队用户的记录 |
| 普通用户 | 仅本团队已启用且已暴露的模型，与 `/v1` 复用授权 | 仅自己的记录 |
| 未分配团队的管理员 | 拒绝模型测试 | 没有日志访问范围 |

普通用户未分配团队时，仍可查看自己的历史日志，但不能调用模型。团队管理员和普通用户均不能通过传入其他 `team_id` 扩大范围。`team_id` 是网关管理参数，转发前会从上游请求体移除。

列表、分页总数、会话详情、模型/状态码/协议汇总、Token 统计以及删除操作统一使用 `LogScope`。零值或无效范围拒绝全部记录，不能把 `user_id=0` 理解为全局。客户端提供的 `session_id` 可以重复，因此每次会话相关查询都必须先应用相同授权范围，再聚合。普通用户不能借与他人相同的会话编号读取对方记录。

现有 `api_logs` 没有历史团队快照，团队管理员的范围按用户**当前**团队归属解析；用户迁移团队后，其历史日志也随该用户进入新团队的管理范围。无所有者的历史日志只对 root 可见。本次没有新增数据库列或迁移。

回归测试：

```sh
# 无数据库也运行角色与团队边界测试；集成部分默认 skip。
go test ./internal/handlers -run '^TestSecurity' -count=1

# 完整集成验证只接受明确指定的本机 disposable security_fix 数据库。
SECURITY_TEST_DATABASE_URL='postgres://USER:PASSWORD@127.0.0.1:PORT/security_fix?sslmode=disable' \
  go test ./internal/handlers -run '^TestSecurity' -count=1
```

集成测试在独立 schema 内执行实际 PostgreSQL 查询，覆盖相同会话 ID 的跨用户、跨团队和空所有者数据，检查所有聚合、分页、详情和删除范围；模型调用指向 `httptest` 本机上游，未授权请求不得产生上游调用。不得将环境变量指向业务数据库。
